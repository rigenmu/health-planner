# 每日工作流

用于接收、合并和整理一天中的零散健康记录。

## 建立当前跟踪清单

只启用与用户目标、既定计划或实际记录有关的项目。可以包括：

- 昨夜睡眠、起床和主观恢复；
- 晨起身体情况、排便或症状；
- 体重及称重条件；
- 血糖、单位、测量时间和空腹／餐后条件；
- 血压、心率、测量时间和与用药的关系；
- 用户报告的药物、补充剂和注射；
- 正餐、零食、饮品和饮水；
- 活动或运动；
- 压力、情绪和身体反馈。

不要自动启用全部字段。排便、咖啡、饮水、零食等只有属于当前计划、已经被用户记录，或影响正在讨论的问题时才持续显示。

## 日期和归日

- 使用用户所在地的自然日期和当地时间。
- 午夜后补记前一晚的晚餐、夜宵、用药或睡前测量时，归入实际发生的日期。
- 一段睡眠按起床所在日期显示为“昨夜睡眠”；入睡时间仍保留真实日期和时间。
- 相对日期无法可靠判断且会影响记录时，只问一个简短问题。

## 每次收到记录时

1. 提取本次新增或更正的事实，判断日期、时间段、单位和测量背景。
2. 与当天已有记录合并。用户明确更正时更新原记录，不保留两份相互冲突的当前值。
3. 按下列固定顺序重建当天截至当前的时间线：
   1. 昨夜睡眠与起床；
   2. 晨起身体情况；
   3. 晨间测量；
   4. 早餐、晨间饮品与晨间用药；
   5. 午餐与日间状态；
   6. 下午饮品、加餐、活动、饮水、压力和身体反馈；
   7. 晚餐与晚间用药；
   8. 晚间测量与睡前状态。
4. 判断当前跟踪项目的状态。
5. 使用固定输出结构回复，并在时间线中给本次新增或更正加上“本次新增”或“本次更正”。

用户连续快速发送多条碎片时，可以等其说完后再合并反馈；不要对同一组语音转写片段重复生成多份回复。

## 状态定义

- `已记录`：用户已明确报告事实或完成情况。
- `待确认`：用户表达了计划、准备或可能完成，但尚未明确确认；也用于会影响判断的单位、药名或时间条件不清。
- `已到时间，尚未记录`：该项目属于当前计划，按用户日程现在通常应当发生，但用户尚未报告。
- `稍后记录`：项目属于今天的计划，但正常时间尚未到。它不是缺项。
- `明确未完成`：只有用户明确说忘记、跳过或没有完成时才能使用。

不在当前计划中的项目不显示状态。不要把“未报告”改写成“没做”。

## 数据整理规则

- 保留原始数值和单位；仅在有帮助时换算，并标明换算结果。
- `kg` 与“斤”前后不一致时确认。
- `136/85/75` 可能表示收缩压／舒张压／心率；上下文不清时确认。
- 同一次测量的重复读数保留原值，可以计算该测量组均值。
- 不把不同日期、不同空腹／餐后条件或不同服药背景的测量混合平均。
- 用户未要求时，不根据随意的饮食描述虚构热量、营养素、钠或分量；需要估算时给范围并说明误差。
- 跨日期出现相同数值不代表重复。只有能够确认是同一次测量被重复描述时才去重。

## 当天结束和换日

用户明确说当天结束、提供当天最后一项晚间记录，或次日补充前一晚入睡时间时，完成日结。日结后新消息默认进入新的自然日；补记旧日内容仍应写回实际日期。
