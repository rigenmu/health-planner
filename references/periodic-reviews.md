# 主动周期复盘

## 触发：由助手检查，不等用户要求

每次互动检查；日结先合并当日材料、按已授权方式归档，再次检查。只要窗口结束且尚未在对话交付，主动发起。普通互动中的复盘已属于本 Skill 的工作，不需每周期重新问“要不要复盘”。

- 起点：沿用已确认周期起点；初次建立用首次纳入正式记录的自然日期为第 1 天。导入历史不擅自重置周期；变更起点需要保留原因和旧状态。
- 每 7 天：固定连续窗口，第 1–7、8–14、15–21 天等。
- 每 14 天：固定连续窗口，第 1–14、15–28 天等；比较前后两个 7 日子窗口。
- 每月：自然月；首月从纳入记录日期开始，并注明不完整自然月。月度不是固定 28 天或 30 天。
- 最后一日已经收尾时可立即复盘；否则在次日及之后首次互动时发起。第 13 天结束不构成完整 14 天窗口，不能提前写成完整双周复盘。
- 到期不等于数据齐全。照常交付复盘，标出覆盖天数与样本不足；不能因缺少某次测量无限延后。
- 同日到期合并呈现，以月度、双周、周的顺序选择主体，明确列出实际覆盖的各窗口，并完成它们各自需要的比较，不能只换标题。不同结束日的逾期复盘可在一次交流中补交，但必须分析相应窗口，不能静默标为完成。
- 用户主动要求当前未结束窗口时，提供“截至当前的阶段回顾”，不标为完整周期已交付。用户明确暂缓、急症优先时保留待交付状态；恢复互动后接续。

有 Python 和已授权长期状态文件时，可调用只读的 [周期检查工具](../scripts/review_schedule.py)：

```bash
python3 scripts/review_schedule.py --state /path/to/private-records/review-state.json
```

它仅计算到期窗口，不读健康日志、不写状态、不建立定时任务、不推送。先从可见对话核对上次是否已经交付，再调用；无执行能力时按同样日期规则计算，不能跳过复盘。

## 交付：文件不是终点

1. 从原始或已核对的结构化记录重新计算。使用日结刚归档的最新数据；文件不可用时注明只基于可访问对话，不声称已写入。
2. 在当前对话清楚说明复盘范围，先给主要发现，再完整展开分析、依据、调整和讨论。不仅发链接或说“复盘已生成”。周回顾较短；双周和月度要充分解释，不套日常简版长度。
3. 已授权保存时留存独立报告和生成状态。准备发送不等于已交付：能够确认助手消息实际出现在对话后才记录交付时间和消息引用；若本轮无法在最终回复后写文件，下次互动先核对那条实际消息再补标。
4. 对已生成但找不到交付消息的报告，核查是否已被补记或更正影响，必要时重算，然后直接在对话补交。不得仅因文件存在而跳过。
5. 提出一两个确实影响计划的问题，接着讨论执行难点。建议与用户已接受计划分开；用户未回答也不能反复重发整份报告。
6. 用户接受调整后更新计划及评估节点。下次复盘检查执行、效果和负担，不只分析新数字。

缺少或不确定交付状态时先检查可访问对话，不默认已交付，也不盲目重发。用户返回很久以后，优先处理当前问题，然后有序补上仍有价值的逾期分析。

## 分析内容

| 内容 | 要求 |
|---|---|
| 数据基础 | 日期、时区、每类指标有效样本及覆盖天数、条件一致性、缺失与估计 |
| 量化变化 | 绝对变化和必要的相对变化；区分持续变化与单日波动，不能只比较最低值 |
| 与目标的关系 | 指标、食欲、体能、症状和执行负担一起看；不把下降等同于健康改善 |
| 相关模式 | 使用重复事件及时间关系，说明其他解释与缺口，不据此证明因果 |
| 上轮安排 | 哪些建议被接受、实际执行、困难何在；未知不能当作失败或漏服 |
| 下阶段计划 | 最多一两项生活方式调整，依据、观察指标、评估时间和提前求助条件 |
| 交流与就医 | 重要分歧／缺口的一两个问题，必要时给医生或药师的核对摘要 |

体重采用同条件 7 日均值或中位数，报告样本数；不把一次急降当减脂成果。血压先计算测量组均值，再分别汇总早晚／服药背景。血糖区分空腹、餐后具体时点、随机。睡眠区分卧床、估计睡眠和主观恢复。活动不把模糊描述换算成精确分钟，饮食不捏造营养量，压力不由自评分直接诊断。

医学解释与具体建议执行 [安全与证据](safety-and-evidence.md)，引用适用来源并说明不确定性。观察期不足就明确说不足；不能默认两周证明疗效，也不能仅凭改善建议减药。症状加重不等待周期结束。

计算过程保留精度，展示时采用与测量精度相称的小数位；样本稀疏时称“已记录数值的均值”，不能暗示每天都有观测。

## 月度重点

在周和双周分析上，回到长期目标、基线与月内变化，检查方案可持续性、反复问题是否得到解决、是否需要复诊或调整跟踪项目。与上月比较时同时说明两个窗口是否完整、样本与测量条件是否相近；没有上月数据就作为首月基线。下个月继续保留少数重点，结束已无必要的额外打卡。

## 后台与通知

本规则的默认触发是用户互动或归档事件。没有新互动时自动运行需要宿主的实际定时能力；用户授权建立定时任务后才配置，确认任务创建结果和可访问数据。不要因改写 Skill 就声称定时提醒已经生效，也不要假定远程任务能读本机文件。
