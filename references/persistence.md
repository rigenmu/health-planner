# 持久化与迁移

用户明确要求长期档案并同意保存位置后才能创建文件；已有明确授权持续沿用。普通对话也能维护相同逻辑，不要求用户管理文件或安装脚本。

## 文件职责

保留既有基础文件，按实际功能增加计划和复盘资料，不创建无用途的空文件：

| 文件 | 内容 |
|---|---|
| profile.md | 已确认长期情况、目标、习惯、个体医嘱、跟踪清单、偏好、时区和来源 |
| daily-log.md | 按时间线保存每日事实；原始陈述或可追溯的来源引用 |
| measurements.csv | 逐次测量原值、单位、条件、组标识及来源 |
| current-status.md | 当前日进度、未解决问题、计划与复盘状态的简要导航 |
| change-log.md | 重要更正、归日、迁移及受影响报告的修订记录 |
| care-plan.md | 当前目标、建议与已接受计划、执行证据、问题事件和跟进触发条件 |
| review-state.json | 周期起点、时区、收尾日期、报告生成与对话交付状态 |
| reviews/ | 每次实际生成的独立复盘报告；保留范围与修订版本 |

## 事实与来源

- 将事实、计算结果、助手假设、医生指示、助手建议和用户接受的计划分开。每个可影响判断的事实应能追溯到原始消息／附件／用户确认。
- 量化记录尽量保留稳定的事件 ID、发生时间（含时区或时间精度）、接收时间、来源、单位、条件和测量组；无法恢复的字段留未知，不补造。
- 原始值与换算／组均值分开；更正保留被替代关系。跨日期相同数值不是重复。
- 凌晨事件保留实际日期，可用关联字段链接前一天的睡前流程，不复制数据。汇总必须说明采用的日期口径并去除同一事件的重复关联。
- 医嘱及用药方案有确认来源和时间；方案继续有效不能代替当天服药完成证据。建议只有得到用户认可后才进入已接受计划。

## 保存时机

沿用用户已选择的每日集中归档方式：白天碎片先合并在当前对话，日结／次日补记收尾时写入。实时保存只有在用户选择且宿主支持时启用。待跟进事项和复盘状态在可访问上下文中先保持连续，授权归档时一并保存，不为规则内部状态反复询问保存许可。

日结后检查复盘到期，并在当前对话交付。准备写入不等于写入成功；验证实际文件后才能报告已归档。写入失败不妨碍对话分析，但应说明未保存并保留待重试事项。

## 复盘状态格式

以下是虚构的结构示例；不要将示例日期当作用户基线。`closed_through` 表示已完成收尾判断的日期，不代表之前每天都填满记录。

```json
{
  "schema_version": 1,
  "anchor_date": "2026-01-01",
  "timezone": "Asia/Shanghai",
  "closed_through": "2026-01-14",
  "reviews": [
    {
      "period_ids": ["7d:2026-01-08:2026-01-14", "14d:2026-01-01:2026-01-14"],
      "report_path": "reviews/2026-01-14-two-week.md",
      "generated_at": "2026-01-14T22:00:00+08:00",
      "delivered_at": null,
      "conversation_ref": null,
      "discussion_status": "pending"
    }
  ]
}
```

- `period_ids` 只能包括报告实际分析覆盖的窗口，不能用合并呈现掩盖遗漏。自然月 ID 使用 `month:起始日期:结束日期`，首月可以是部分月份。
- `generated_at` 表示报告确已生成。`delivered_at` 和 `conversation_ref` 只在确认实际回复已交付后填入；计划输出、草稿和文件路径都不是消息交付证据。
- 最终回复后没有写文件机会时，下次先从可访问对话核对并补上消息引用，再计算待交付窗口；用户无需再确认一次。
- 讨论待回复不阻止下周期到期，也不触发重复发送旧报告。明确延期记录原因及恢复条件，不能虚报已交付。
- 历史补记或更正改变结论时生成带说明的修订并在对话解释，保留旧报告及交付历史。周期工具只检查常规到期，不判断医学影响或报告失效。

## 旧版迁移与跨端

保留旧数据和已同意的位置，不重新初始化档案。清理旧四栏目规则及“只生成文件”的流程说明，用当前呈现和交付规则替代；不得删除原始健康事实。先备份受影响文件，建立字段映射，核对事件数量、来源、测量条件与关键汇总，再切换新版。旧报告没有交付记录时先查对话，有证据才补标，否则在当前对话补交。

公共 Skill 更新和私人数据迁移分开：更新 Skill 不自动授权访问、修改全部私人档案。用户已经授权迁移时按其范围执行，不重问同一许可。

新对话仅在实际获得档案／授权增量来源后恢复上下文。未来 Plugin 可沿用这些字段，但不会自动让手机读取本地文件。跨端存储需身份校验、按人隔离、稳定事件 ID、冲突更正及导出／删除机制；未实现时不宣称已有。个人数据不进入公共 Git 历史，也不默认用于群体统计。
