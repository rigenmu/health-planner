# 持久化规则

只有用户明确要求建立长期档案，并同意保存位置后，才创建或维护文件。普通使用保持在当前对话中，不要求用户管理文件。

## 建议结构

```text
health-records/
├── profile.md
├── daily-log.md
├── measurements.csv
├── current-status.md
└── change-log.md
```

- `profile.md`：目标、当前跟踪清单、已确认的长期情况、既定方案和用户偏好。
- `daily-log.md`：按自然日和早晚顺序保存睡眠、饮食、用药、活动、压力和身体反馈。
- `measurements.csv`：保存体重、血糖、血压、心率等逐次量化数据及测量背景。
- `current-status.md`：最近一次日结和近期回顾快照。
- `change-log.md`：只记录重要的用户更正、历史归日和数据规则变化。

简单需求可以只使用 `profile.md` 和 `daily-log.md`，不要为了形式创建空文件。

## 写入频率

- 白天收到的碎片先在当前对话中合并，不因每条消息频繁写文件。
- 用户完成当天最后一项晚间记录、明确说“今天结束”，或次日补充前一晚入睡时间后，集中完成一次日结写入。
- 如果用户明确要求实时写入，按其要求执行。
- 跨天补记应更新实际发生日期，不重复创建记录。

## 写入要求

- 文件中的每日材料与回复使用同一条从早到晚的时间线。
- 量化数据保留原值、单位、时间、测量条件和分组标识。
- 用户更正后同步更新所有受影响文件；有必要时在 `change-log.md` 记录原因。
- “未报告”“待确认”和“明确未完成”必须分开保存。
- 7 日和 14 日结果从结构化记录重新计算，不从旧总结复制数值。

## 隐私

- 健康档案必须位于 Skill 目录之外。
- 不把个人数据提交到 Skill 的 Git 仓库。
- 不主动上传、同步或连接第三方服务。
- 用户要求迁移或云同步时，先说明目标位置、访问范围和隐私影响，再执行。
