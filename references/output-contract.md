# 对话呈现

## 日常呈现

固定逻辑为：今日进度时间线 → 简短说明待办／缺口 → 一段 💬 合并反馈与主要行动。取消旧的“今日记录／今天还差什么／当下点评／下一步”四栏目要求。

- 标题为“今日进度｜日期 · 当前时段”。使用用户语言。
- 原生 Markdown 引用块形成轻量时间线；每个时间段一块，块间用空行。时间标签后空一个引用行，正文另起一段；不依赖 HTML、特殊空格、手绘竖线、行尾空格或客户端卡片能力。
- 使用起床后、上午、午后、晚上、睡前等符合当天实际的时间段。有准确时间才写时刻。段内按事件先后排列，早晚项目尽量对称，但不为对称改变顺序或创建空项。
- 随手补充用简版：旧时段各用一两句概括，本次更新展开。测量已记录可以概括，但当前异常、未解决症状、影响决策的数值及测量条件不能藏掉。
- 查看全天或日结用完整版：展开所有已报告事项，保留测量原值、单位、背景及相关饮食细节。展示压缩不能覆盖原始记录。不能把未报告字段补成正常。
- 不使用逐项无序列表作为日常主界面，不生成新 HTML、附件或可视化。用户明确要求图表或可视化时再处理。
- 只将本次新增／更正内容加粗，下一次恢复普通文字；纯查看全天不重复高亮上一轮数据。单词更正只强调更正范围。新事实加粗一次，不在顶部、时间线和反馈中重复强调。
- 到期事项和稍后事项放在对应时间段或末尾，择一呈现。自然说明当前还留什么；无缺项不等于健康正常。用户说过“睡前再测”后，不每条重复催促。未启用项目不列缺口。

## 反馈是一段对话

用 💬 起一段自然的话，接住本次输入，解释最相关变化，再顺着说到一个主要行动。不要分别列“点评”“建议”“下一步”。重要行动用一个简短加粗片段，标点放外面。

- 记录表达准确，反馈表达自然；不道德化评价饮食，不因体重下降或活动时长多就机械表扬。
- 建议回应当前目标和已接受计划；适用的行动可以延续，不为了显得有用而反复新增喝水、早睡或补报任务。
- 没有需要调整之处就直接说明。只有答案会改变评估或行动时才追问，优先一两个问题。
- 不能在“一件事”中藏进服药、测量、饮食和休息等多个任务。日常一项行动限制不适用于急症所需的多个立即步骤。
- ❗仅用于具体、需特别注意的风险，不作为日常装饰。急症内容先于进度，不等到末尾。
- 用户提问时先回答；同时有新增记录则附简版进度。专项分析和周期复盘允许充分的段落、表格、依据与讨论，不强塞进日常的一段话。

## Markdown 可靠性

遵循 [CommonMark 强调规则](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)。中文标点也参与定界符判断：即使星号成对，中文标点紧挨关闭标记、后面又接中文时，也可能不被解析为加粗。不能把所有失败都归因于转义。

发出前检查：

1. 只输出渲染用的 Markdown 文本；不输出 JSON 字符串、转义后的星号、字符实体代替星号，或用反引号包裹正常回复。
2. 加粗采用两侧各两个 ASCII 星号；内容首尾为文字／数字，内部不留首尾空格。外围引号和句末逗号、句号、冒号等放在加粗范围外。加粗不跨段、不嵌套链接或另一层强调。
3. 中文连续句子优先加粗短语，再接普通标点。示意：`💬 今天先按计划继续，**明早再一起回顾**。` 这是源码示例；实际健康回复不得套代码标记。
4. 引用块、列表、表格与普通段落之间留空行，不能把 💬 段落误接进时间线引用块。发布前使用 [解析检查](../scripts/check_response.py) 验证代表性回复；不要每次日常记录都为排版运行程序。
5. 收到显示失败反馈时，重发整段修正版，保留原意。若宿主仍显示星号，改用普通文本和自然提示保证可读，说明尚未验证宿主显示；不承诺 Skill 能修复所有客户端渲染缺陷。
