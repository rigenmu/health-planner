# 按需生成个人档案

## 从最少文件开始

没有长期保存需求时直接在当前可访问对话中使用。有需要且已获保存位置授权后，由助手按已确认信息生成并维护私人 Markdown，用户不用先建模板或填表。已有位置与授权继续沿用；没有就只问一次必要的保存位置。

新档案可先用一份 `health-context.md`，包括：

- 个人约定：语言、反馈偏好、时区、当前跟踪项目、保存时机、复盘频率。
- 健康背景与当前计划：已确认目标、相关健康史及医嘱来源、用户接受的行动、观察方式与评估时间。
- 接续状态：当前日期、未归档记录、未解决问题与跟进节点、复盘起点和交付／讨论进度。

只填已知且有用的信息，不预生成空白字段或把建议当作本人规则。先在对话中应用用户明确的偏好，在既定保存时机沉淀；不要每次更新重写整份文件或重问许可。随着日志增长，按实际需要拆出日记、测量表或独立复盘报告，并保留简短索引。无需预设一整套文件名、数据库或自动化代码。

如果用户希望其健康专用文件夹里的 `AGENTS.md` 帮助后续接续，只在该范围补充健康任务的读取入口，指向个人约定文件，保留原有无关规则。不要覆盖全局 AGENTS.md、把健康偏好强加给其他工作，或复制整份 Skill。普通 Markdown 是否会被自动加载取决于宿主；只有实际读到才能声称已恢复。个人偏好不能把未知变成事实或放宽医学边界。

## 旧档案与历史导入

已有 `profile.md`、`daily-log.md`、测量表、计划或复盘状态文件继续使用，不强制换名、合并或删除。旧 JSON 可继续读写；精简 Skill 不意味着重置数据，也不自动授权私人迁移。仅在用户要求调整结构时备份受影响文件、建立映射并核验后迁移。

导入只读用户指定的对话／文件及相关完整分页。用户原始陈述、明确更正和可读报告优先于旧助手总结；保留单位、条件、真实日期和来源，合并碎片、去重并保留更正关系。相同数值跨日期不算重复。恢复已接受计划、未解决问题和复盘起点／实际交付状态；无法确认是否仍有效的历史用药保留为待核对。

说明实际覆盖范围、数量、缺口和重要歧义；原始历史不可访问时不能称为完整迁移。只问影响判断的缺项。核验原值、事件数量及关键汇总后记录导入截止位置，后续只合并增量。

## 保存与接续

沿用已约定的保存方式；新用户可建议每日收尾集中归档，用户也可选择其他节奏。写入后确认成功再说已保存，失败则保留待归档内容。每次只读取接续所需的个人约定、近期日志与状态，专项分析再补读相关历史。

个人文件留在已授权位置，不进入 Skill、公共仓库或未经授权的外部存储。更新 Skill 时保留个人文件；新对话或设备需要实际访问档案后才能接续，不能把安装当作同步。
