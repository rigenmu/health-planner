# 主动复盘

## 何时发起

沿用已确认的起点和时区；首次建立时以正式纳入记录的自然日期为第 1 天。默认周窗口为第 1–7、8–14 天等，双周为第 1–14、15–28 天等，月度为自然月，首月不足整月须注明。更新或迁移 Skill 不重置起点。

每次互动及日结归档后检查：窗口最后一天已收尾则立即复盘，否则在窗口结束后的首次互动发起。第 13 天不能完成 14 天复盘。缺记录照常分析并说明覆盖，不无限等待补齐。用户提前要求时称阶段回顾，不标为完整周期。

同日到期合并一次呈现，以较长周期为主，保留各窗口所需比较；逾期可合并补交，但不能把未分析窗口标为完成。用户明确延期或急症优先时保留待办，下次接续。用户可在个人约定里调整频率，记录新的起点／范围而不改写历史。

## 讲清什么

在对话中先讲主要发现，再展开有依据的分析：

- 日期范围、每类指标样本数与覆盖天数、缺失及条件差异。
- 可比较的数据变化、与目标的关系及可能解释；不把单日波动当疗效。
- 上轮已接受计划的执行、效果和困难；未知保持未知。
- 下阶段一两项可讨论的调整、观察指标、评估时间，以及必要的就医沟通。

周回顾抓近期变化，双周比较前后两个 7 日窗口，月度检查长期目标和可持续性；与上月比较需说明覆盖是否相近。体重用同条件均值或中位数，血压先保留组内原值再算组均值、区分早晚与服药背景，血糖区分空腹和餐后时点。报告样本数，不将稀疏数据冒充每日观测；计算显示精度与原测量相称。

医学解释执行 [健康建议](health-guidance.md)。分析后提出一两个影响计划的问题，讨论得到接受的调整进入个人计划，下次检查结果。复盘不受日常“一段反馈”的篇幅限制。

## 记住是否交付

在当前可访问对话或已授权的私人 Markdown 中，保留周期起点、时区、已收尾日期、下一到期范围，以及报告生成／对话交付／讨论进度。不要求 JSON 或脚本。

文件存在不等于已向用户讲解。先核对实际消息，已讲解的不重发；只有文件的先检查是否需要重算，再在对话补交。记录实际交付日期和可追溯消息依据，不能将草稿标为已发送；本轮来不及落盘时下次核对消息后补记。讨论待回复不阻碍下周期，也不触发整份报告反复发送。补记改变旧结论时保留并解释修订。

主动复盘指互动和归档时自行发起。无人发消息时定时运行，需要宿主支持且用户另外授权配置；不能仅因 Skill 已安装就承诺后台提醒。
