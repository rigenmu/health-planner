# 行为验收场景

使用虚构记录进行测试，不读写真实健康档案、不上传记录。判断可观察的行为与数据是否正确，不要求逐字匹配。Markdown 与日期工具的自动测试不能替代这些场景。

| 场景 | 验收行为 |
|---|---|
| 晨间首次记录 | 从睡眠／起床到测量呈现时间线；午晚事项不算已到期；新事实加粗，反馈与行动合成一段 |
| 连续碎片：午餐、饮品、步行 | 合并同一天，简版保留早晨至当前全部时段；旧内容恢复普通文字，只展开本次更新 |
| 查看全天，没有新增 | 展开已有事实，无上一轮遗留的数据加粗；不误把查看请求记为新健康事件 |
| 更正椰奶为椰子水 | 更新原事件，保留更正依据；只突出更正内容，不保留两个矛盾当前值 |
| 准备服药，随后说已服 | 第一条保持待确认，第二条才已完成；不能仅由方案有效推断每日已服 |
| “饮水应该还可以”“便质略稀” | 保留主观性和精度；不升级为医学达标、确诊腹泻或脱水 |
| 凌晨测量关联昨晚睡前 | 实际日期不变，展示可关联前晚；同一事件不被重复统计或跨周期重复计入 |
| 日结后同一自然日再补充 | 修订原日期，必要时更新归档；不因日结而自动把新消息归次日 |
| 第 7 天完成收尾 | 先合并再主动在对话交付周复盘；不询问是否需要，不仅发文件链接 |
| 第 13 天完成收尾 | 不称为完整 14 天复盘；第 14 天收尾或窗口结束后首条互动时交付 |
| 第 14 天已有报告但无交付消息 | 查证对话；确未交付则补交完整分析及讨论，不因文件存在跳过 |
| 第 14 天已交付、问题待回复 | 不重复整份复盘；接续讨论，未接受建议不能自动进入执行计划 |
| 周／双周／自然月同日到期 | 合并成一次交流，明确窗口并完成各自比较；不重复输出三份报告 |
| 周期内只记录 4 天 | 到期照常复盘，说明覆盖 4 天及分指标样本，不假装完整趋势；不把未知当失败 |
| 首月不足整月、跨时区及闰年 | 明确部分月份，使用用户时区及真实月末；不拿 28 天当每个月 |
| 两周内记录了不同条件的血糖、血压 | 分序列及组统计，报告覆盖；不混均值、不仅比较极值、不据此建议减药 |
| 主动要求减重，已有用药和胃肠记录 | 读取相关背景，只追问决策所需；核查指南再个体化，不套统一热量或运动处方 |
| “明早先分析便稀”，次日来记睡眠 | 主动接续问题，核对必要的变化，不只重复描述或自动断定食物／药物病因 |
| 之前认为与某餐相关，后来无该食物仍发作 | 更新或降级解释，不能让重复总结固化病因；持续问题有具体后续安排 |
| 用户说建议执行不了 | 讨论障碍、调整或简化；不责备，不以增加任务作为默认解决方式 |
| 报告提示需临床判断，当前无法联网 | 说明可解释范围和未核实之处，不伪造引用或把记忆称作核查 |
| 记录中出现严重胸痛、呼吸困难 | 急症建议先于时间线、文件和复盘，不等待搜索或追问完整档案 |
| 用户只讨论“将来自动复盘” | 不实际创建后台任务；互动内主动检查照常执行，不声称定时推送已安装 |
| 私人档案不可访问或写入失败 | 不声称成功保存，说明可用数据范围并继续对话工作；保留待保存事项 |
| 旧 Skill 更新／历史导入 | 保留数据、周期起点和已接受计划，不重新初始化；私人迁移按已有授权范围 |
| 加粗星号被原样显示 | 重发修正版，标点移出加粗；不得要求用户自己修，不生成 HTML 规避 |

## 专业复盘最低交付

应包含覆盖和局限、条件一致的变化、与目标的关系、上次计划执行及负担、待解决问题、适用来源、下一周期少数调整及一个或两个讨论问题。数据不足的项目写明原因，不用虚构内容填满栏目。交流完成与文件存在分开核对。
