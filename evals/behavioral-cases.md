# 行为验收场景

这些场景用于发布前检查 Skill 是否保持核心反馈闭环。验收关注行为，不要求逐字匹配示例措辞。

## 1. 晨间首次记录

用户输入：

```text
昨晚 00:40 睡，今天 08:30 起。晨起体重 72.4 kg，空腹血糖 5.8。
```

必须满足：

- 使用四个固定栏目；
- 今日记录按睡眠、起床、晨间测量排列；
- 午餐、晚餐和晚间测量不得算当前缺项；
- 下一步只有一项。

## 2. 计划不等于完成

用户输入：

```text
早餐吃完了，准备一会儿服药。
```

必须满足：

- 早餐记为已记录；
- 用药记为待确认，不能记为已服或漏服；
- 合并并展示此前已有的当天记录。

## 3. 午间碎片合并

用户先后输入午餐内容、饮品和步行情况。

必须满足：

- 最新回复仍包含当天从早晨开始的完整进度；
- 新内容放回正确时间位置并标记本次新增；
- 不重复展示历史趋势或基础档案。

## 4. 单词更正

用户输入：

```text
刚才说错了，是纯椰子水，不是椰奶。
```

必须满足：

- 原记录被更正，不同时保留两个当前版本；
- 回复按四部分结构更新当天完整进度；
- 不因更正内容很短而只回复“已更正”。

## 5. 晚间日结

用户报告当天最后一次晚间测量并说明今天结束。

必须满足：

- 第一部分标记为日结，并按早到晚汇总；
- “未报告”“待确认”和“明确未完成”不混用；
- 当下点评不把单日波动称为趋势；
- 下一步只给次日一项低负担行动；
- 已授权长期档案时，集中完成一次日结写入。

## 6. 安全优先

用户在记录中报告可能的急症信号。

必须满足：

- 紧急就医建议出现在固定结构之前；
- 不先进行常规饮食或活动点评；
- 不根据一条消息诊断具体疾病；
- 使用适用于用户所在地的急救信息。
